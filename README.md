# 🔥 คู่มือแอปตรวจจับไฟและควันด้วย AI (Telegram Alert)

แอปพลิเคชันแจ้งเตือนอัคคีภัยอัจฉริยะ สำหรับรันบนบอร์ด Arduino Dragonwing เพื่อตรวจจับ **"ไฟ"** และ **"ควัน"** ผ่านกล้องแบบเรียลไทม์ พร้อมหน้าจอควบคุม (Dashboard) และแจ้งเตือนเข้า Telegram ทันทีเมื่อเกิดภัยพิบัติ

---

## 💡 โครงสร้างและหลักการทำงานของแอป (Architecture & Working Principle)

แอปพลิเคชันนี้ทำงานร่วมกันระหว่าง **แอปพลิเคชันฝั่ง Python (Backend)** และ **หน้าจอควบคุมเว็บแอป (Frontend)** โดยรันอยู่ภายในระบบ Docker Container บนบอร์ด Arduino Dragonwing:

### 1. การทำงานของระบบวิเคราะห์ภาพด้วย AI (AI Core)
* **การสลับโหมดกล้อง (INPUT_MODE):** 
  * **โหมด MOBILE (กล้องมือถือ):** ตัวแอปพลิเคชันจะรันเซิร์ฟเวอร์เพื่อให้แอป *Arduino IoT Remote* บนสมาร์ทโฟนสตรีมภาพเข้ามา จากนั้นตัวช่วยประมวลผล (Brick: `video_object_detection`) บนบอร์ดจะวิเคราะห์วัตถุในแต่ละเฟรมโดยตรง
  * **โหมด WEBCAM (กล้อง USB):** โค้ด Python จะดึงภาพจากกล้อง USB ที่เสียบเข้ากับบอร์ด และใช้ตัวรันโมเดลสำเร็จรูป (`ImageImpulseRunner`) ในการทำนายภาพแต่ละเฟรม
* **ระบบการจับคู่ผ่าน QR Code (Secure OTP Pairing):** ในโหมดกล้องมือถือ แอป Python จะสุ่มสร้างรหัส One-Time Password (OTP) ขนาด 6 หลักขึ้นมาแบบสุ่มปลอดภัย จากนั้นหน้าเว็บจะนำข้อมูลการเชื่อมต่อและรหัสผ่านนี้ไปแสดงผลเป็น **QR Code** เพื่อให้ผู้ใช้สามารถนำแอปมือถือสแกนเชื่อมต่อและสตรีมภาพด้วยการเข้ารหัสความปลอดภัยได้อย่างสะดวกและรวดเร็ว
* **การวาดกรอบวัตถุ (Bounding Box Rendering):** เมื่อ AI วิเคราะห์พบวัตถุประเภท `fire` (ไฟ) หรือ `smoke` (ควัน) ที่มีความมั่นใจเกินเกณฑ์ ระบบจะนำเฟรมภาพดิบมาวาดกรอบสี่เหลี่ยมสีแดงครอบจุดที่เป็นไฟ และสีน้ำเงินครอบจุดที่เป็นควัน พร้อมเขียนบอกเปอร์เซ็นต์กำกับ

### 2. ระบบแจ้งเตือนและการทำงานของ Cooldown (Telegram Gateway)
* **เกณฑ์การแจ้งเตือน (Threshold):** หากความมั่นใจในประเภท `fire` (ไฟ) สูงถึงเกณฑ์ที่ตั้งไว้ในตัวสไลด์ของหน้าเว็บ (เช่น 70%) ระบบจะกระตุ้นการแจ้งเตือน
* **ระบบป้องการการแจ้งเตือนซ้ำ (Cooldown Lock):** เพื่อไม่ให้ระบบส่งภาพสแปมเข้ามือถือและทำให้เซิร์ฟเวอร์ทำงานหนัก โค้ดจะใช้ระบบล็อคความปลอดภัยแบบ Thread-safe จำกัดความถี่ในการส่งภาพ **สูงสุด 1 ภาพ ต่อ 20 วินาที**
* **การทำงานแบบเบื้องหลัง (Background Threading):** โค้ดจะส่งคำร้องขอไปที่เซิร์ฟเวอร์ Telegram API แบบเบื้องหลัง (Thread แยก) เพื่อไม่ให้ความหน่วงในการส่งเน็ตเวิร์กไปรบกวนความลื่นไหลของการประมวลผลกล้องหลัก

### 3. การแสดงผลและการสื่อสารผ่าน Socket (Web UI & Socket.io)
* การคุยกันระหว่างโค้ด Python และหน้าเว็บ Dashboard ใช้เทคโนโลยี **Socket.io** เพื่อส่งข้อมูลหากันทันที (Real-time):
  * **Python -> เว็บแอป:** ส่งข้อมูลเฟรมวิดีโอ, เปอร์เซ็นต์การตรวจพบไฟ/ควัน, และสถานะการส่งข้อความ Telegram
  * **เว็บแอป -> Python:** ส่งค่า Threshold ที่ผู้ใช้ปรับด้วยสไลเดอร์บนหน้าเว็บกลับไปควบคุมเกณฑ์ตรวจจับของโค้ดแบบเรียลไทม์

## 🤖 การจัดเตรียมและเรียกใช้งานโมเดล AI (Edge Impulse Model Setup)

แอปพลิเคชันนี้ใช้โมเดลตรวจจับวัตถุของ Edge Impulse (ไฟล์นามสกุล `.eim`) ในการวิเคราะห์หาไฟและควัน โดยในโปรเจกต์นี้ใช้ชื่อไฟล์มาตรฐานคือ `wildfire-dt-model.eim`

### 📹 วิธีการสร้างและเทรนโมเดล AI ด้วยตัวเองจากคลิปวิดีโอ
หากต้องการพัฒนาหรือสร้างโมเดลตรวจจับวัตถุของตัวเอง (เช่น นำคลิปวิดีโอมาสร้างเป็นโมเดลสำหรับหาไฟหรือควัน) สามารถทำตามคลิปวิดีโอสอนบน YouTube ได้ที่นี่:
👉 **[ลิงก์วิดีโอสอนบน YouTube]** *(ผู้ใช้งานสามารถนำลิงก์มาวางทับส่วนนี้ได้เลย)*

**ขั้นตอนโดยย่อ:**
1. อัปโหลดคลิปวิดีโอตัวอย่างเข้าไปในระบบของ **Edge Impulse**
2. ติดป้ายกำกับ (Label) วัตถุ และสั่งรันเทรนโมเดลตรวจจับวัตถุ (Object Detection)
3. ไปที่หัวข้อ **Deployment** -> ดาวน์โหลดโมเดลในรูปแบบบล็อคสำเร็จรูปสำหรับระบบ **Linux (ARM64)** (จะได้ไฟล์นามสกุล `.eim` ออกมา)
4. เปลี่ยนชื่อไฟล์โมเดลที่ดาวน์โหลดมาให้เป็น **`wildfire-dt-model.eim`** แล้วนำมาจัดเก็บลงในโฟลเดอร์โปรเจกต์นี้แทนไฟล์เดิม

### 🔍 หลักการดึงโมเดลไปใช้งานในแต่ละโหมดกล้อง
เมื่อจัดเตรียมไฟล์โมเดล `wildfire-dt-model.eim` ไว้ในโปรเจกต์แล้ว ตัวแอปในแต่ละโหมดกล้องจะเรียกใช้งานโมเดลตัวนี้ด้วยวิธีที่ต่างกัน ดังนี้ครับ:

#### 📷 1. โหมด WEBCAM (ใช้กล้อง USB ต่อตรงเข้าบอร์ด)
* **ใครเป็นคนรันโมเดล?**: **ตัวแอป Python เอง** (ประมวลผลภายในโค้ด `python/main.py`)
* **ดึงไฟล์โมเดลจากไหน?**: **ดึงจากโฟลเดอร์โปรเจกต์โดยตรง** (ที่พาธ `/app/wildfire-dt-model.eim`)
* **สรุปการใช้งาน**: โหมดนี้สะดวกที่สุด เพราะตัวโค้ด Python จะไปดึงไฟล์โมเดลที่อยู่ในโฟลเดอร์แอปที่คุณแตกไฟล์ไว้ขึ้นมาใช้งานได้เลยโดยอัตโนมัติ ไม่ต้องคัดลอกไฟล์โมเดลย้ายไปที่อื่นครับ

#### 📱 2. โหมด MOBILE (สแกน QR Code ใช้กล้องมือถือ)
* **ใครเป็นคนรันโมเดล?**: **ตัวประมวลผลสำเร็จรูป (Brick: `video_object_detection`)** ซึ่งเป็น Container อีกตัวที่รันแยกต่างหาก ไม่ใช่ตัวโค้ด Python
* **ดึงไฟล์โมเดลจากไหน?**: **ดึงจากโฟลเดอร์ส่วนกลางของบอร์ด** ที่พาธ: `/home/arduino/.arduino-bricks/ei-models/wildfire-dt-model.eim` *(ตามที่ระบุสั่งไว้ในตัวแปรของไฟล์ `app.yaml`)*
* **สรุปการใช้งาน**: เนื่องจากตัวประมวลผลกล้องเป็น Container แยกที่ไม่มีสิทธิ์เข้าถึงโฟลเดอร์แอปของคุณโดยตรง มันจึงต้องดึงโมเดลจากพื้นที่ส่วนกลางของบอร์ด ดังนั้นผู้ใช้จึงต้องคัดลอกไฟล์โมเดลจากโฟลเดอร์แอป ไปใส่ไว้ที่โฟลเดอร์ส่วนกลางของบอร์ด (ผ่านวิธีส่งด้วย ADB ในคู่มือหัวข้อถัดไป) โหมดกล้องมือถือนี้จึงจะทำงานได้ครับ

## 🔍 หน้าที่และส่วนประกอบหลักของไฟล์ในโปรเจกต์ (Code Components)

* **`app.yaml`** (ไฟล์คอนฟิกโครงสร้าง): ทำหน้าที่บอกบอร์ดว่าโปรเจกต์นี้ต้องการดึงความสามารถ (Bricks) อะไรมาใช้บ้าง ได้แก่ ตัวประมวลผลภาพกล้องมือถือ (`video_object_detection`) และส่วนหน้าเว็บอินเตอร์เฟส (`web_ui`)
* **`python/main.py`** (โค้ดควบคุมหลัก): เป็นสมองของฝั่ง Backend ทำหน้าที่ควบคุมลูปการดึงภาพ, ประสานงานโมเดล AI, จัดการ Cooldown และยิงคำสั่งแจ้งเตือนไปยัง Telegram API
* **`python/requirements.txt`** (ไฟล์ติดตั้งส่วนเสริม): ระบุความต้องการของแพ็กเกจ `edge_impulse_linux` เพื่อให้บอร์ดไปดาวน์โหลดไลบรารีตรวจจับภาพมาติดตั้งตอนเริ่มทำงาน
* **`assets/index.html` & `assets/style.css`** (หน้าตาเว็บ): จัดโครงสร้างและดีไซน์หน้าจอแดชบอร์ดให้เป็นธีมมืดและมีลักษณะโปร่งแสงแบบกระจก (Glassmorphism Dark Theme) แสดงผลข้อมูลได้สวยงามน่าใช้งาน
* **`assets/app.js`** (สคริปต์แดชบอร์ด): เป็นสมองฝั่งเว็บ ทำหน้าที่รับส่งสัญญาณข้อมูล Real-time, วาดระดับเกจวัดไฟ/ควัน, คำนวณเวลารีเซ็ตเกจเป็น `0.0%` เมื่อไม่เจอวัตถุใน 1.5 วินาที และควบคุมตัวสไลด์ความไว
* **`toolsformobiletest/`** (โฟลเดอร์สคริปต์อัตโนมัติของโหมด MOBILE): บรรจุไฟล์สคริปต์ `push_models.sh` (สำหรับ macOS) และ `push_models.bat` (สำหรับ Windows) เพื่อช่วยส่งโมเดลไปยังพื้นที่ส่วนกลางของบอร์ด (`/home/arduino/.arduino-bricks/ei-models/`) และตั้งสิทธิ์ `chmod 777` อัตโนมัติ
* **`tools_refreshmodel/`** (โฟลเดอร์สคริปต์อัปเดตโมเดลของโหมด WEBCAM): บรรจุสคริปต์ `refresh_models.sh` และ `refresh_models.bat` สำหรับส่งไฟล์โมเดลไปอัปเดตที่โฟลเดอร์แอปบนบอร์ดโดยตรง เพื่อใช้งานร่วมกับกล้อง USB (Webcam) และสั่งทำ `chmod 777` ให้เรียบร้อย

## 🚀 วิธีการใช้งานอย่างง่าย (Simple Usage)

1. **สั่งรันแอป:** กดปุ่ม **Run** ใน Arduino App Lab
2. **เปิดหน้าเว็บแอป:** 
   * หากเลือกใช้กล้องมือถือ (`INPUT_MODE = "MOBILE"`) หน้าเว็บจะแสดง **QR Code** ขึ้นมา ให้ใช้แอป **Arduino IoT Remote** บนมือถือสแกนเพื่อเชื่อมต่อกล้อง
   * หากใช้กล้อง USB (`INPUT_MODE = "WEBCAM"`) หน้าเว็บจะแสดงภาพจากกล้องขึ้นมาทันที
3. **ปรับระดับการแจ้งเตือน:** 
   * ด้านขวาของหน้าจอจะมีสไลเดอร์ **Telegram Threshold** คุณสามารถลากปรับได้ เช่น ตั้งไว้ที่ 80% (หมายถึงต้องเจอไฟชัดเจนเกิน 80% ขึ้นไปเท่านั้นบอทจึงจะส่งรูปเตือนเข้ามือถือ)
4. **ดูประวัติ:** 
   * ในแถบ **Telegram Gateway** ด้านล่างขวา จะคอยสรุปจำนวนครั้งที่บอทส่งแจ้งเตือนสำเร็จ และแสดงเวลาของการแจ้งเตือน 5 ครั้งล่าสุดให้เห็นตลอดเวลา
